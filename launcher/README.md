# COD3 PC Launcher - author tools 0.1.1 / player launcher v2 (0.2.0)

Launcher v2 adds a left-hand Campaign/Multiplayer menu, battlefield artwork,
compact JARC and original-game Treyarch credits, and optional quiet battle
ambience. The audio preference is remembered and audio pauses while the game
runs. Read docs/LAUNCHER-V2.md for installation and artwork credits.

Author tools now reuse unchanged build files and skip matching cloud objects
with small metadata checks. Read docs/INCREMENTAL-UPDATES.md when upgrading an
existing author folder. Existing player launchers already skip matching files.

This kit contains the compiled Windows player launcher, your publishing tools,
the update-service source, tests and build source. It does not contain the
original game, map payloads, textures, private signing keys or credentials.
Those are selected from your existing installation when you prepare a release.

Your existing multiplayer directory is live at
https://cod3-master.hovgtv.workers.dev. This kit targets a separate update
service at https://cod3-updates.hovgtv.workers.dev, in the same Cloudflare
account. Update hosting was configured and the first signed release was
published after the initial kit was delivered. This author-tool upgrade does
not change your live release or require deploying the Worker again.

## First setup on Justin's PC

1. Extract the ENTIRE ZIP into a permanent folder. Do not run its CMD files
   directly from the ZIP or move a CMD file away from its sibling folders.
2. Run SETUP-HOSTING.cmd. It checks your Cloudflare CLI login, creates or reuses
   the private cod3-port-updates R2 bucket, and deploys the read-only update
   Worker. R2 must already be enabled. Storage/request charges can apply beyond
   Cloudflare's allowances; there is no new payment or subscription activation
   automated here. The expected health response initially says published:false.
3. Close COD3 and stop making changes to the release install, then run
   BUILD-RELEASE.cmd. GAME-FOLDER.txt points at your current install; edit that
   text file if it moves. The tool inventories, compresses and signs the files
   into release-candidate without uploading them.
4. Review release-candidate/inventory.json and test the selected build. Then run
   PUBLISH-RELEASE.cmd. It verifies local files and remote object hashes, uploads
   missing/corrupt objects, stores a release snapshot, and updates stable.json
   LAST. Players only see the new release after this final step.
5. Distribute the ENTIRE player folder, including public-key.xml generated by
   BUILD-RELEASE.cmd. Zip that folder if desired. Players need their own already
   extracted COD3 PC port installation. They do not need Node, Python or Wrangler.

The private signing key is created on your PC at
%LOCALAPPDATA%\HOVGtv\CoD3Publisher\private-key.xml. Keep a private backup. Never
include that key in the player package or upload it to the update bucket.
If this key is lost, the tool refuses to silently replace the identity already
trusted by your player folder. Restore it before publishing another release.

## What the player launcher does

- Selects and remembers an existing installation containing both base game
  executables and the extracted campaign/multiplayer XEX markers.
- Checks a signed online release each time it opens and installs changed files.
- Provides Campaign, Multiplayer, folder selection and Verify / Repair.
- Includes all six map packs: Champs, Bravo, Valor, Carentan, Seelow, SeelowNight.
- Selects all finished textures/replace content, including nested campaign/map
  replacements and UI/menu assets; raw dumps and diagnostic files stay out.
- Brings custom weapon/mantle data, runtime DLLs and the repacked tank/mortar
  dependencies used by your existing friend update.
- Updates the master_server INI entry to the new multiplayer directory when
  launching. Names, peer addresses, controls, graphics and saves are retained.
- Applies the existing friend-update gameplay dependency defaults during a
  completed content update, rather than overwriting the entire INI.
- Verifies chunk and whole-file hashes, reuses completed download chunks,
  backs up originals, journals installation, and verifies recovery backups.
- Keeps known damaged managed installations blocked until repair succeeds.
  An unmanaged pre-existing install can still launch if the update service is
  unavailable. Newer local development versions are not downgraded.

Do not overwrite files manually while an update is in progress. The launcher
and updater share a lock; it also checks that the game is closed before writes.
Backups and chunk cache are under the installation's .cod3-launcher directory.
Backups are retained. Cache/backup housekeeping and launcher self-update are
not implemented in this first build.

## Validation and remaining checks

Synthetic real-file tests cover installation, multi-chunk assembly, corruption,
interruption/retry, repair, rollback, startup recovery, path attacks, preservation
of user data, signing-key continuity, output-junction rejection and launch locks.
The UI construction test verifies the three main controls and preview safety.
Node tests exercise the Worker's read-only routing, health and responses.

The actual install inventory at preparation was version 0.5.867, 317 selected
files, approximately 3.25 GiB uncompressed; details are in docs/INSTALL-INVENTORY.json.
No writes were made to the live installation or original game source.

The initial R2/Worker setup and first release upload were completed after
delivery. Still required: a real two-PC update/repair and campaign/multiplayer
playtest, plus a publishing run with the new incremental author tools. A health
response alone does not prove a game session can be joined.

Source maintenance: BUILD.ps1 compiles and runs the .NET 4.8 tests; run
node --test tests/worker.test.mjs for the Worker tests. Use x64 Windows.
